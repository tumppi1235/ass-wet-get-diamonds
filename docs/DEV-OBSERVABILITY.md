# Private dev failure references — TR-117 foundation

Unexpected shared API failures now return a fresh reference code in the player/admin error message, JSON response and `X-Trail-Reference` header. The matching application log record contains only a fixed service/event, reference, allowlisted operation/method, status 500 and a coarse built-in error category. It excludes request URLs/queries, headers, identity, bodies, coordinates, routes, exception messages and stacks. The reference is generated by the server, not accepted from a supplied header.

Normal validation, authorization and concurrency responses retain their existing status and are not recorded as unexpected server incidents. A failed logger does not suppress the safe response. No player/audit/reward rows are written by diagnostics, and no new monitoring service, credential or notification subscription is introduced. This is development only; production remains untouched.

## Support use

When a playtest receives an unexpected service error, retain its reference code and approximate time. An authorized maintainer can inspect the existing dev Site's Worker logs for that code and coarse operation, then reproduce with synthetic inputs. No real-player GPS route, request payload, password or private snapshot is needed in a public GitHub incident. Do not deliberately corrupt live state to test the failure path.

The new record's privacy guarantee is tested at the application boundary; this does not establish the hosting provider's access-log content, retention, availability or alerting. Production dashboards/alerts, availability metrics, alert routing/ownership and provider retention remain pending. A reference code alone is not a complete monitoring or disaster-recovery system.

## Evidence

Synthetic canary tests include private-looking query/header/body/exception contents and prove none appears in the diagnostic record or safe response. The actual API catch path is exercised with an isolated throwing database adapter; response/log references match. Authorization failures keep status 401 without incident noise, unknown operations become `other`, and logging failure still returns a bounded 500. No hosted failure or player write was induced.

The complete 119-case regression suite, mobile/server typecheck/lint, Worker build and code-only structural graph pass for this increment. The unchanged Expo game export is reused for this server-only release.
